使用 Clash 节点的流程可以概括为四步：**导入前确认订阅格式与客户端版本匹配，导入后定期更新订阅，按用途选择节点或代理组，出现问题时按“订阅—节点—本地设置”的顺序排查**。本文聚焦已经买好服务之后的实际操作；如果你还在挑选服务，请先看[Clash 机场订阅怎么选](/guides/clash-airport/)。

## 先了解：现在的 Clash 客户端用的是什么内核

原 Clash 项目已经停止更新，目前常见的 Clash 系图形客户端，大多改用 Mihomo（原名 Clash Meta）作为内核。Mihomo 沿用了 Clash 的 YAML 配置结构，并支持更多协议和功能。因此你在客户端里看到的节点、代理组和规则，基本都遵循 Mihomo 的配置规范。遇到配置相关的问题时，优先查阅 Mihomo 官方文档。

## 导入订阅前的检查清单

导入之前花一分钟确认以下几点，可以避免大部分“导入了却用不了”的情况：

1. **订阅格式**：服务后台提供的是 Clash（Mihomo）配置订阅，还是通用订阅？不同客户端支持的格式不同；
2. **客户端版本**：使用仍在维护的版本，过旧的客户端可能不认识新协议；
3. **协议支持**：节点使用的协议需要被你的客户端内核支持；
4. **链接完整**：复制订阅链接时不要多出空格或少了字符；
5. **网络环境**：首次下载订阅需要能访问服务提供的订阅地址。

## 订阅更新：为什么要更新，怎么更新

服务商可能会调整节点地址、增减节点或更新配置，所以订阅需要定期更新。在 Mihomo 的配置里，通过订阅获取的节点属于“代理集合”，常见字段包括：

| 字段 | 作用 |
|---|---|
| `type` | 集合类型，通过链接获取时为 `http` |
| `url` | 订阅地址 |
| `interval` | 自动更新间隔，单位为秒 |
| `health-check` | 健康检查，可设置检测地址、间隔、超时和期望状态码 |
| `filter` | 按关键词或正则只保留部分节点 |

图形客户端一般也提供手动更新订阅的操作。当你发现节点大面积失效时，第一件事就是手动更新一次订阅。

## 节点选择与代理组

导入后，客户端通常会按配置生成若干代理组。Mihomo 支持的常见类型有：

- **select**：手动选择，适合想自己决定用哪个节点的情况；
- **url-test**：定期测试延迟并自动选择，`tolerance` 可设置切换容差，避免频繁跳动；
- **fallback**：当前节点不可用时，按列表顺序切换到第一个可用节点；
- **load-balance**：在多个节点之间分配连接。

日常建议：浏览网页可以使用自动选择组；对稳定性要求高的场景，例如视频会议，可以手动固定一个表现好的节点。怎样判断节点好不好，见[稳定节点怎么看](/guides/stable-nodes/)。

## 常见问题的排查顺序

遇到连接问题时，按以下顺序逐项排查，效率最高：

1. **节点列表为空**：检查订阅链接是否完整、是否过期，再手动更新订阅；
2. **全部节点超时**：先确认本地网络正常，再更新订阅；仍然不行，到后台确认套餐是否到期或流量是否用尽；
3. **部分节点超时**：属于正常现象，切换到其他节点即可，并观察是否长期如此；
4. **能连接但网站打不开**：检查客户端的代理模式与规则设置，确认系统代理已开启；
5. **导入时报格式错误**：确认订阅格式与客户端支持的格式一致，不要把通用订阅当作 Clash 配置直接导入。

排查时如果需要截图求助，记得把订阅链接打码，原因见[安全机场如何判断](/guides/safe-airport-guide/)。

## 日常维护的小习惯

- 定期更新订阅，尤其是在服务商发布节点调整之后；
- 客户端保持更新，但升级前留意版本说明；
- 备份自己修改过的配置，避免更新后丢失；
- 不把订阅链接分享给他人。

使用 Clash Party 的读者，可以继续阅读[Clash Party 机场配置指南](/guides/clashparty-airport/)。

## 要点总结

- 当前主流 Clash 客户端大多基于 Mihomo 内核，配置问题优先查 Mihomo 文档；
- 导入前确认订阅格式、客户端版本和协议支持；
- 订阅需要定期更新，节点大面积失效时先手动更新；
- select、url-test、fallback 等代理组适合不同场景；
- 排错按“订阅—节点—本地设置”的顺序进行。
